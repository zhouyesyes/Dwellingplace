# 工作间聊天与附件检查

流式正文按 50 毫秒批量更新，工作间 Markdown 独立组件只解析变化的正文；普通聊天也缓存正文解析。工作间使用独立滚动区域和流布局输入区，并跟随 visualViewport 高度。没有关闭流式输出。

附件使用现有服务器口令及内部桥接钥匙鉴权，不引入云服务。每条最多 4 个，每个非空且不超过 20 MiB；支持 PNG/JPEG/GIF/WebP、MP4/WebM、PDF/TXT/MD/CSV/JSON/ZIP。服务端复核数量、任务归属、扩展名、MIME 和常见二进制签名，文本拒绝 NUL，JSON 验证语法。签名检查不是完整格式解码或病毒扫描。SVG/HTML、可执行文件及未列出的格式拒绝上传。

附件二进制放在服务器挂载的 `/work/.qisuo-attachments/<随机编号>/`，目录和文件由连接程序创建，Codex 只能读取；元信息保存在私有桥接数据目录。文件名清理路径分隔符、控制字符和开头的点；下载使用随机编号及任务归属校验，普通文件强制下载，附加 nosniff 和 sandbox 响应头。当前系统为单主人共享口令，并无多用户账号权限体系。消息 JSON / 浏览器数据库仅存元信息，不存二进制。

历史记录展示图片和视频预览及普通文件下载。“直接用 Codex”通过正文中的本地只读路径供工具读取，没有采用未经确认的模型图片/文件输入协议；“和他一起”仅给伙伴元信息及路径，需要他交给 Codex 读取。视频能否播放取决于浏览器编解码能力，未接入视频理解。附件只支持选择，未增加拖放。

上传后发送失败或离开页面，未关联的文件会保留在服务器；为遵守不删除数据的要求，没有自动清理。移除待发送附件只取消本次选择。

离线检查（先用现有 Vite 起本地服务，不安装依赖）：

- `npm run build`
- `node --check deploy/qisuo-server/server.mjs`
- `node --check deploy/qisuo-server/codex/bridge.mjs`
- `node scripts/chat-stream-check.mjs`
- `node scripts/workroom-attachments-check.mjs`
- `node scripts/workroom-ui-check.cjs`（依赖已全局安装的 Playwright，服务地址 127.0.0.1:5199；建议启动全新 Vite 进程，避免 HMR 模块版本影响模拟状态）

UI 脚本拦截非本机请求；模拟长历史和高频流式事件，检查输入聚焦、附件移除、视口缩小并输出浅深色截图到 /tmp。服务端脚本在临时目录执行实际处理函数，验证附件校验和发送关联，不启动 Codex 或访问账号。项目未配置 lint、类型检查或测试脚本。

人工验收：服务器重新运行安装部署桥接和转发修改后，用真实工作间分别在两种模式上传上述类型，检查重开任务的附件、下载和 Codex 读取路径；真机 Safari/Android 测试键盘弹出、连续生成时输入、向上滚动不被拉回以及视频播放。当前离线模拟未证明真实模型/设备组合都正常，也没有建立真实掉帧率基线。
