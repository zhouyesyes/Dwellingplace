# 个人设备绑定与同步（2026-10-15）

栖所是单人空间，不新增账号系统。所有已绑定设备共用服务器原来的 `DATA_DIR/sync` 数据、索引及 rev；不创建按设备划分的数据副本。浏览器 IndexedDB 是离线缓存及编辑区，冲突仍按已有版本号/三方合并流程处理。

## 日常操作

1. 已绑定设备打开「设置 → 同步」（页面标题为「设备与同步」），点「生成绑定码」。
2. 新设备打开**同一个栖所网址**，进入同步页，输入设备名称和绑定码。
3. 绑定码 5 分钟有效，只能签发一台设备；重新生成会作废该签发设备之前的码。新设备收到自己的长期凭证，之后自动同步，不填写同步 URL 或主口令。
4. 「已绑定设备」可以撤销任意单台，包括当前设备。撤销立即阻止后续云端请求，正在上传的数据在落盘前再次检查权限。已经交付的数据/遗失设备的离线副本无法远程抹除。

现有依赖 `jsqr` 只支持识别，没有二维码生成器。本轮不安装依赖，页面保留禁用的「二维码绑定（待支持）」入口。

## 鉴权与凭证

- 新接口是 `/sync/*`；公开发现接口 `GET /.well-known/qisuo-sync` 只返回协议版本及 `/sync` 路径，没有凭据。
- 每台设备一份独立的 256 bit 级凭证，通过 `Authorization: Bearer …` 发送。新绑定、迁移流程的请求地址、绑定码和日志均不含服务器主口令或长期凭证。
- 凭证只存在本机 IndexedDB 的 `sync:conf.device`，不进 Vue store、同步内容、普通备份或链接。清理网站数据后需要重新绑定。浏览器同源脚本仍有读权限，因此这不是硬件保险箱或 HttpOnly 会话；要求 HTTPS、可信部署、正常的设备锁屏保护。
- 服务器 `DATA_DIR/sync-devices.json`（600）保存凭证摘要、设备记录、绑定码摘要/到期/使用记录、限流计数，以及用于幂等签发的随机服务端密钥。不保存原始设备凭证、主口令或原始绑定码。目录须保持 700；该账本也属于敏感备份。
- 绑定码采用 12 位 32 字符字母表（约 60 bit），由密码学随机数生成。10 分钟内每来源地址最多 10 次兑换请求、全站最多 30 次；每设备最多生成 5 次。计数持久化，重启不能绕过。使用直连 socket 地址，不信任可伪造的转发 IP；反代下多台设备共享限额，正常只需少量操作。
- 本机随机请求凭据保证响应丢失时安全重试：同一迁移请求、或有效期内同一已消费绑定码的同一本机请求，只返回同一台设备的同一凭证，不签发第二台。不同请求使用已经消费的绑定码会失败；已撤销设备的请求凭据不能恢复权限。
- 撤销签发设备，也作废它尚未兑换的绑定码。账本损坏时拒绝服务，不悄悄重建成空账本。当前服务按**单个 Node 进程/单实例**运行，不支持多实例同时写同一账本。
- Service Worker 不缓存同步/发现接口和带 Authorization 的 GET；升级激活时只移除旧同步响应缓存，不清网页资源、IndexedDB 或云端数据。

## 旧设备升级：无损但不能绕过撤销

- **服务器仍是旧版**：发现不到新协议时保留旧同步行为，界面提示先升级服务器。这个兼容阶段原有含口令 URL 仍属于旧协议；新服务器迁移和绑定不向这些地址发请求。
- **首台旧设备**：从已有 `sync:conf` 或服务器 API 配置取出原凭据，通过 `/sync/migrate` 的 Authorization 请求自动转换为独立设备凭证。保留同一份云端数据、seq、known、消息合并基线及待上传项，不清库、不重建数据。
- **后续旧设备**：首台迁移后，原 `/p/<主口令>/sync/*` 全部拒绝，主口令也不能再换取新的设备凭证。页面解释需从已绑定设备获取绑定码；绑定到同一服务器时保留原合并基线，本地离线内容合并上去。
- 不能继续放开“有主口令就自动领新凭证”，否则遗失设备即使被撤销，也能借缓存中的旧 API 配置重领权限。这是后续旧设备需要绑定码的原因。
- 高级配置折叠保留原同步地址迁移及公开服务器域名；普通使用不需要打开它。不要在消息、日志、截图或 URL 中分享长期凭据。

## 自动同步与剩余限制

沿用启动拉取、visibilitychange 可见/pageshow/focus/online 拉取，可见时每 20 秒轮询；保存后约 1.5 秒上传，失败/未完成项约 5 秒后重试，请求 30 秒超时。启动核对本地指纹补回未落盘的待同步记账；meta/消息待保存和模型生成期间保护本地编辑。设备凭证失效时停止同步，保留本地内容并提示重新绑定，绝不退回主口令。

写入带 rev，409 取最新再合并；消息已有基线时三方合并，没有基线时云端同 id 正文优先、本地新增 id 保留。无法判断的冲突优先云端；本地完整冲突副本在 `sync:conflict:<时间>:<键>`，不上传、不进普通备份，暂无恢复 UI，可在浏览器开发者工具 IndexedDB 中取回。消息基线会增加本地占用。多标签页没有编辑锁；服务端数据文件/索引还没有数据库级跨文件事务。本轮提供的是固定单空间的个人设备鉴权，不是完整账号、实时协作或无冲突数据库。

设备撤销只控制**栖所同步接口**。原模型代理、工作间等功能仍使用原有鉴权；旧 meta 中已有的其他 API 配置不会擅自删除或轮换。若设备遗失且曾保存其他服务口令，仍需在对应服务单独处理。

## 由主人批准后部署（本轮未执行）

1. 先审核本地提交并由她在工作间点「推上线」。本轮按要求不联网、未拉取远端；推送前需要再拉最新并检查冲突。
2. 在服务器备份完整持久化数据目录（包括原 `data/sync` 和新增的 `data/sync-devices.json`，若已存在）。不要更换 DATA_DIR，不要清空挂载卷。新增账本会自动建立，无需改主口令或手工填凭证。
3. 她批准后，使用项目原来的安装命令重新运行服务器安装：

   ```sh
   bash <(curl -fsSL https://raw.githubusercontent.com/zhouyesyes/Dwellingplace/main/deploy/qisuo-server/setup.sh)
   ```

   安装涉及联网、镜像构建和容器重建，必须由她执行或明确授权。`setup.sh` 已增加复制 `devices.mjs`；自建镜像部署也必须同时部署 server/sync/devices 三个模块，并继续挂载同一个 DATA_DIR。单实例运行。
4. 反代在同一个 HTTPS 域名下把 `/.well-known/qisuo-sync` 和 `/sync/*` 交给 Node；保留 Authorization 请求头，不缓存这些响应，不把请求体或 Authorization 写进访问日志。同源自建服务器**没有新增必填环境变量**。
5. 若仍用 GitHub Pages 等独立网页域名，需要在该前端构建时设置公开的 `VITE_SYNC_ORIGIN=https://你的数据服务器域名`（只有 origin，没有路径/口令）。当前 Pages workflow 不注入此变量；如需构建时预设，应在独立的构建环境提供它，不需修改 workflow。未配置时默认同源发现，高级配置可临时指定公开域名。GitHub Pages 与数据服务器在不同域名时属于跨源部署，不能把 Pages 当作数据服务。不要填 Secret 或主口令。
6. 刷新最常用的旧设备，确认自动迁移成功、旧聊天仍在，再依次绑定其他设备。先保留至少一台可用设备；确认列表和撤销正常后再处理遗失设备。

**所有设备都遗失/被撤销时**：不能在网页拿主口令绕过撤销。需要主人批准服务器端恢复：停止服务、备份全部数据与账本、把旧设备账本移到服务不会读取的受保护备份位置，再启动，以首台旧配置重新引导。不能删改 `data/sync`。旧凭证在新账本中不再有效；若有泄露风险还需另行轮换其他服务口令。这一步会作废全体设备绑定，不能当作正常的单设备撤销操作，也不由应用自动执行。恢复或回滚到旧服务前应确认不会重新开放遗失设备持有的主口令权限。
